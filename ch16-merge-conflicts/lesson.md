# 16. Merge Conflicts

Git combines most changes from two branches without help. A merge conflict happens when both branches change the same lines, and Git cannot tell which version you want. It stops, marks the lines in the file, and waits for you to decide. Conflicts are normal in shared code, and the fix is always a decision about what the code should say.

This chapter creates a conflict on purpose in your copy of the practice repository. You will read the markers Git writes, use the merge editor to choose the result, and commit the resolved merge.
