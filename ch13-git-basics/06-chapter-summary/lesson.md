# Chapter summary

Remember these as you commit:

- The Changes list holds edited files. The Staged Changes list holds the files you chose for the next commit.
- A commit message has a short first line that says what the commit does.
- Commit Staged saves the staged files to your local history. Nothing reaches GitHub until you push.
- The status bar shows the current branch, and clicking it opens the branch menu.

```quiz
Where does a file go when you stage it?
○ The Changes list, with its other edits
→ That is where a file sits before you stage it.
○ The status bar
→ The status bar shows the branch. It does not hold files.
◉ Staged Changes
→ Yes. The staged files are the ones the next commit will include.
```

```quiz
Which commit message describes the change best?
◉ Add a comment to the report
→ Yes. It is short, in the present tense, and says what the commit does.
○ stuff
→ A message like stuff tells the reader nothing about the change.
○ I changed some things, fixed a few bugs, and tidied the layout while I was in there
→ That mixes several ideas. Use one commit for each idea.
```

```quiz
Where do you find the name of the branch you are on?
○ The Test Explorer
→ Test Explorer lists tests and their results.
◉ The status bar, at the bottom of the window
→ Yes. Clicking the name opens the branch menu.
○ The Solution Explorer
→ The Solution Explorer shows projects and files, not branches.
```
