# 12. Unit Tests in Test Explorer

Running the program shows you what happens for one set of inputs, and only if you watch it. A unit test does that check for you, every time. It calls one method with known input, compares the result with the answer you expect, and reports a pass or a fail. When you change code later, you run the tests again and see at once whether anything broke.

This chapter uses the test project in the practice solution, Pricing.Tests. You will look at a test written with NUnit, run tests in Test Explorer, read a failure message, and think about what a passing test does and does not prove.
