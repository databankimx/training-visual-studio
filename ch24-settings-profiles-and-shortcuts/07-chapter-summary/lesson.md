# Chapter summary

Remember these about settings and shortcuts:

- Tools > Options holds the settings. Its search box finds a setting by name, so you rarely need to scroll the tree.
- Import and Export Settings saves your settings to a file and loads them back. Read a settings file before you share it, because it can hold folder paths and account names.
- A mapping scheme is a named set of shortcuts, and it changes all of them at once. A rebind changes one command. Both are saved on your computer only.

```quiz
Where do you go to find a setting when you do not know which page holds it?
○ The Extensions menu
→ Extensions holds add-ins. It does not hold settings.
◉ The search box at the top of the Options dialog
→ Yes. Type part of the setting's name, and the matching settings appear.
○ The Solution Explorer
→ The Solution Explorer shows your files, not your settings.
```

```quiz
You are about to share your exported settings file with a colleague. What should you do first?
◉ Open the file and read it for folder paths and account names.
→ Yes. A settings file can hold details about your computer, so check it first.
○ Send it straight away, because settings cannot hold anything private.
→ A settings file can record paths and account names.
○ Commit it to the team's shared repository, so everyone gets it.
→ A settings file is for your computer. Read it before it goes anywhere.
```

```quiz
You rebind Solution Explorer on your computer. What happens on a teammate's computer?
○ The shortcut changes for everyone who opens the solution.
→ A rebind is saved on the computer where you made it.
○ The shortcut changes for everyone who uses the same Visual Studio account.
→ Your settings are saved on your computer, not with the solution.
◉ Nothing changes, because the rebind is saved only on your computer.
→ Yes. Each computer keeps its own keyboard settings.
```
